# Биодент+ — сайт стоматологической клиники

## Что это за проект

Одностраничный сайт-визитка для стоматологической клиники в Оше (Кыргызстан).

Проект делается как **демо для холодного захода к клиникам**. Разработчик заметил,
что у стоматологий в Оше почти нет сайтов, и хочет прийти к ним с готовым
работающим примером, а не с предложением «давайте сделаем».

Из этого следует главное архитектурное требование: **сайт должен
перенастраиваться под любую другую клинику за 20 минут**. Это не проект под
одного заказчика, это шаблон, который будет показан 10–15 клиникам.

«Биодент+» — рабочее название для демо. В Бишкеке есть реальная клиника
`biodent.kg` — это **другая** организация, не путать. При реальном запуске
название будет заменено.

## Стек

- Next.js 15, App Router
- React 19, TypeScript
- Tailwind CSS v4 (CSS-first конфигурация через `@theme` в `globals.css`,
  файла `tailwind.config.ts` нет)
- Шрифт Onest через `next/font/google`
- Никакой базы данных. Никакого бэкенда на Python. Всё статика + один route handler
- Деплой на Vercel

Стек не финальный. Если предлагаешь альтернативу — объясни trade-off, не меняй молча.

## Структура

```
config/clinic.ts          Единственный источник данных о клинике
app/layout.tsx            Шрифт, метаданные
app/page.tsx              Сборка секций по порядку
app/globals.css           Tailwind + @theme с палитрой
app/api/lead/route.ts     Приём заявки → Telegram
components/Section.tsx    Обёртка секции (отступы, заголовок, тёмный вариант)
components/*.tsx          Секции страницы
public/clinic/            Фотографии клиники
```

### Порядок секций на странице

1. `Header` — sticky, навигация по якорям, кнопка «Записаться»
2. `Hero` — тёмно-зелёный экран, заголовок, два CTA, полоса цифр
3. `Advantages` — 4 карточки «почему к нам возвращаются»
4. `Services` — 8 услуг, клик открывает попап с описанием
5. `Doctors` — сетка врачей
6. `Process` — 4 шага лечения, тёмная секция
7. `Reviews` — 4 отзыва + ссылка на 2ГИС
8. `Faq` — аккордеон на нативном `<details>`
9. `Booking` — форма заявки
10. `Contacts` — телефон, адрес, режим, карта
11. `Footer`
12. `WhatsAppFab` — плавающая кнопка, только мобилка

## Правило конфигурации

**Ни одна строка про конкретную клинику не должна попасть в компоненты.**

Всё — название, контакты, услуги, врачи, отзывы, FAQ, тексты hero — живёт
в `config/clinic.ts`. Компоненты знают только структуру данных.

Если добавляешь секцию с текстом — текст идёт в конфиг, а не в JSX.
Проверка: можно ли перенастроить сайт под другую клинику, открыв ровно два файла
(`config/clinic.ts` и блок `@theme` в `globals.css`)? Если нет — рефактори.

Флаг `showPrices` управляет отображением цен. Сейчас `false`: заказчик не хочет
публиковать прайс. Разметка под цены уже написана, включается флагом.

## Дизайн

### Палитра

Определена в `app/globals.css` в блоке `@theme`:

| Токен | Hex | Где |
|---|---|---|
| `brand-900` | `#12403A` | Хедер, hero, секция «как лечим», футер |
| `brand-700` | `#17604B` | Hover тёмных кнопок, акцентные ссылки |
| `brand-600` | `#1D9E75` | Фокус, плавающая кнопка |
| `brand-100` | `#E1F5EE` | Фон секции записи, текст на тёмном |
| `canvas` | `#F3F5F2` | Фон страницы |
| `surface` | `#FFFFFF` | Карточки |
| `ink` | `#14171A` | Основной текст |
| `muted` | `#63706B` | Вторичный текст |
| `hairline` | `#DDE3DD` | Границы и разделители |

Пропорция: фон ~70%, белые карточки ~20%, зелёный ~10%. Зелёный только на
кнопках, хедере, футере и двух тёмных секциях. Если зелёного стало больше — это
ошибка, а не улучшение.

### Типографика

Одна гарнитура — Onest, подключена с сабсетом `cyrillic`. Выбрана потому, что
спроектирована под кириллицу, а не адаптирована с латиницы.

Иерархия строится размером и весом, не декором. Заголовки секций
`text-3xl sm:text-4xl`, h1 `text-4xl sm:text-6xl`, тело 15–16px,
подписи 13–14px. Заголовкам — `tracking-tight`.

### Чего в этом проекте не делаем

Заказчик попросил минимализм. Это ограничение, а не пожелание:

- Никаких градиентов, теней (кроме одной на плавающей кнопке), свечения
- Никаких fade-in / slide-up при скролле. Единственная анимация — поворот
  плюса в FAQ
- Никаких ALL CAPS подписей и «эйбрау»-лейблов над заголовками
- Никаких эмодзи в интерфейсе
- Никаких иконок-картинок из бесплатных стоков (у конкурента именно так, и это
  главное, что делает его сайт дешёвым)
- Никакой нумерации 01 / 02 / 03, кроме секции `Process` — там это реальная
  последовательность
- Разделители между карточками делаем через `gap-px` на фоне `hairline`,
  а не рамками вокруг каждой карточки

### Тон текстов

Спокойный, конкретный, без продающего давления. Стоматология — тревожная тема,
восклицательные знаки и «уникальные технологии» работают против доверия.

Плохо: «Профессиональная стоматология премиум-класса!»
Хорошо: «Стоматология полного цикла в Оше»

CTA называет действие: «Записаться на приём», не «Отправить» / «Подробнее».

## Локальная специфика (важно, не выбрасывать)

Это юг Кыргызстана, не США и не Россия. Отличия влияют на продукт:

- **Ош — двуязычный город.** Кыргызский и узбекский в быту распространены шире,
  чем в Бишкеке. Сайт пока русскоязычный, но структуру текстов держим готовой
  к переводу: все строки в `config/clinic.ts`, никакого текста в JSX. Если дойдёт
  до второго языка — добавляем кыргызский, не английский

- **WhatsApp — основной канал связи.** Кнопка WhatsApp должна быть на равных
  с формой, а не второстепенной. Ссылка формата
  `https://wa.me/996XXXXXXXXX?text=<предзаполненный текст>`
- **2ГИС важнее Google Maps.** Ссылки на карту и отзывы ведут в 2ГИС
- **Instagram — витрина клиники**, ссылка обязательна
- **Онлайн-записи со слотами нет и пока не нужно.** Только заявка: пациент
  оставляет номер, администратор перезванивает. Не ломаем процесс клиники
- Регуляторики уровня HIPAA или ФЗ-152 нет. Достаточно строки о согласии
  на обработку персональных данных под формой

## Форма заявки

`app/api/lead/route.ts` принимает POST и шлёт сообщение в Telegram.

Переменные окружения: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` (см. `.env.example`).

Если переменных нет — заявка пишется в `console.log` и возвращается
`{ ok: true, delivered: false }`. Это осознанно: форму можно тестировать
до создания бота. Не «чинить» это поведение.

Валидация на клиенте: имя не пустое, в телефоне минимум 9 цифр. Ошибка
показывается под полем. Сервер валидирует повторно.

## Приоритеты

1. Работающее демо важнее идеальной архитектуры
2. Mobile-first. Показывать сайт будут с телефона, стоя у стойки ресепшена
3. Скорость загрузки. Целевая метрика — меньше 3 секунд на мобильном интернете
4. Переиспользуемость под другую клинику
5. SEO — потом. Отдельные страницы под услуги нужны для реального запуска,
   но для демо избыточны. Заложить возможность разнести, не делая этого сейчас
